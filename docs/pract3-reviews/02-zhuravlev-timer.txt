## Что делаю

Практика 5, вариант V6.

Разделил `active_timers` на две функции. `close_expired_timers` закрывает просроченные таймеры,
`active_timers` только читает список. В обработчике `GET /timers/active` сначала вызывается
закрытие, потом чтение. Ответ пользователю не меняется.

## Какие файлы трогал

- `backend/app/services/timer_service.py`
- `backend/app/api/timers.py`

Область ревью: примерно 90 строк.

## Было / стало

Было:

```text
def active_timers(db, user_id):
    timers_model.close_expired(db, user_id)
    rows = timers_model.list_active(...)
```

Стало:

```text
def close_expired_timers(db, user_id):
    return timers_model.close_expired(db, user_id)

def active_timers(db, user_id):
    rows = timers_model.list_active(...)
```

Почему так: одна функция одновременно меняла данные и читала их, из-за этого её нельзя было
безопасно вызывать только для чтения.

Что стало лучше: закрытие и чтение тестируются отдельно, а в API видно порядок шагов.

Сколько это стоило бы чинить потом: было 2 ч, стало 0,5 ч.
