# Критерии приёмки User Story

## 1. Рецепты на основе продуктов, которые есть дома

> Как пользователь, я хочу получать рецепты на основе продуктов, которые есть у меня дома, чтобы готовить без лишних покупок.

**Критерии приёмки:**

1. Пользователь может отметить продукты как «есть дома» из списка продуктов/поиска.
2. После отметки продуктов система показывает рецепты, для которых все ингредиенты отмечены как имеющиеся.
3. Для каждого рецепта отображается список ингредиентов и явно показано, какие продукты уже есть, а каких не хватает.
4. Если рецептов с полным совпадением нет, система показывает сообщение «Рецептов только из имеющихся продуктов не найдено» и предлагает рецепты с минимальным количеством недостающих ингредиентов.
5. Если пользователь не отметил ни одного продукта, система просит добавить продукты и не показывает пустой список без пояснения.

---

## 2. Создание собственных рецептов с ингредиентами в граммах

> Как пользователь, я хочу создавать собственные рецепты, указывая ингредиенты и их количество в граммах, чтобы сохранять свои блюда в сервисе.

**Критерии приёмки:**

1. Пользователь может создать рецепт, указав название, хотя бы один ингредиент и его количество в граммах.
2. Поле количества принимает только положительное числовое значение в граммах; значение `0`, отрицательное число или пустое поле не сохраняются.
3. Пользователь может добавить несколько ингредиентов и удалить ошибочно добавленный ингредиент до сохранения.
4. После сохранения рецепт появляется в разделе «Мои рецепты» и доступен для повторного открытия.
5. Если обязательные поля не заполнены, система показывает понятную ошибку и не сохраняет рецепт.

---

## 3. Калорийность и БЖУ на основе данных «ВкусВилла»

> Как пользователь, я хочу видеть калорийность и БЖУ блюда на основе данных о продуктах из «ВкусВилла», чтобы учитывать пищевую ценность при планировании питания.

**Критерии приёмки:**

1. Для рецепта, все ингредиенты которого сопоставлены с продуктами «ВкусВилла» и имеют данные о пищевой ценности, система показывает калорийность, белки, жиры и углеводы.
2. Расчёт отображается как минимум на всё блюдо и на одну порцию; единицы измерения указаны: ккал, г.
3. При изменении состава рецепта, граммовок или количества порций показатели калорийности и БЖУ пересчитываются автоматически.
4. Если для одного или нескольких продуктов нет данных о пищевой ценности, система показывает расчёт по доступным продуктам и явно предупреждает: «Для части ингредиентов нет данных, итог может быть неполным».
5. Если данных нет ни для одного ингредиента, система не показывает некорректный нулевой результат, а выводит сообщение «Недостаточно данных для расчёта БЖУ».

---

## 4. Изменение количества порций и пересчёт граммовок

> Как пользователь, я хочу менять количество порций и автоматически пересчитывать граммовки ингредиентов, чтобы приготовить нужное количество еды.

**Критерии приёмки:**

1. Пользователь может изменить количество порций рецепта на положительное целое число.
2. После изменения количества порций все граммовки ингредиентов пересчитываются пропорционально и отображаются в граммах.
3. Пересчёт выполняется по формуле: `новая граммовка = исходная граммовка × новое количество порций / исходное количество порций`.
4. Калорийность и БЖУ также пересчитываются с учётом нового количества порций.
5. Если пользователь вводит `0`, отрицательное число или нечисловое значение, система показывает ошибку и сохраняет предыдущее корректное количество порций.
6. При округлении граммовок система использует целые граммы и явно отображает итоговые значения; сумма ингредиентов остаётся логически соответствующей выбранному количеству порций.

---

## 5. Добавление недостающих ингредиентов в корзину «ВкусВилла»

> Как пользователь, я хочу добавлять недостающие ингредиенты для выбранного рецепта в корзину «ВкусВилла» и оформлять доставку через сервис, чтобы быстрее покупать всё необходимое.

**Критерии приёмки:**

1. На странице рецепта система определяет, какие ингредиенты уже отмечены как имеющиеся, а каких не хватает.
2. Если недостающие ингредиенты есть, пользователю доступна кнопка «Добавить недостающее в корзину».
3. По нажатию кнопки в корзину «ВкусВилла» добавляются только недостающие продукты в количестве, соответствующем выбранному количеству порций.
4. После добавления пользователь видит подтверждение и может перейти в корзину для проверки состава и оформления доставки.
5. Если недостающих ингредиентов нет, кнопка добавления недоступна или скрыта, а система показывает сообщение «Все ингредиенты уже есть».
6. Если товар недоступен или добавление в корзину не удалось, система показывает ошибку с указанием товара и не добавляет частично некорректный состав без уведомления.

## 6. Пошаговая инструкция с ингредиентами на каждом этапе

> Как пользователь, я хочу видеть пошаговую инструкцию приготовления с количеством ингредиентов на каждом этапе, чтобы готовить блюдо без путаницы.

**Критерии приёмки:**

1. Рецепт отображается в виде упорядоченных шагов приготовления.
2. На каждом шаге показаны ингредиенты и их количество в граммах, необходимые именно для этого шага.
3. Количество ингредиентов на шагах соответствует выбранному количеству порций и обновляется при изменении порций.
4. Сумма ингредиентов по всем шагам соответствует общему списку ингредиентов рецепта с учётом округления.
5. Пользователь может переходить между шагами вперёд и назад без потери выбранного количества порций.
6. Если на шаге не требуются ингредиенты, система явно показывает «Ингредиенты не требуются» вместо пустого блока.

**Дополнительно:** источник шагов уже появился — спринт 3, задача 2 разбирает страницы povarenok.ru
и сохраняет шаги в `recipe_steps` (номер, текст, фото), а порции — в `recipes.servings`
([`docs/povarenok-pages.md`](povarenok-pages.md)). Открытые вопросы для этой истории: у ~58 % страниц
нет количества порций, и страница не говорит, какие ингредиенты относятся к какому шагу — это
придётся решать либо разметкой вручную, либо эвристикой по тексту шага.

## 7. Таймеры в рецепте

> Как пользователь, я хочу видеть таймеры в рецепте, чтобы было удобнее засекать время.

**Критерии приёмки:**

1. У рецепта может быть указано время приготовления в минутах; оно видно в карточке рецепта. Если время не указано (например, рецепт импортирован из датасета), система не придумывает его, а просит ввести длительность вручную.
2. Пользователь может запустить таймер рецепта одной кнопкой: без явной длительности используется время рецепта, а при ручном вводе принимается целое число секунд от 1 до 86 400.
3. Запущенный таймер отображается с обратным отсчётом и остаётся в списке активных таймеров до окончания; отсчёт не сбрасывается при перезагрузке страницы и не зависит от установленного на устройстве времени.
4. По окончании времени система сигнализирует пользователю (звук, вибрация, уведомление) и помечает таймер завершённым; таймер исчезает из списка активных.
5. Пользователь может отменить таймер; отменённый таймер исчезает из списка активных, а повторная отмена даёт понятную ошибку «таймер не найден».
6. Таймеры одного пользователя не видны и недоступны другому пользователю.
7. Если таймеров запущено слишком много (больше 20), система не создаёт новый и объясняет ограничение; если рецепт не найден, система сообщает об этом и не создаёт таймер.

**Дополнительно:** приоритет — High (первая задача спринта 3); зависимости — `openapi.yaml`
(`POST /timers`, `GET /timers/active`, `DELETE /timers/{id}`), `docs/timer.md` (алгоритм отсчёта
и границы точности); открытые вопросы — пауза таймера и звонок при закрытой вкладке (Web Push)
вынесены в отдельные задачи спринта.

6. Если на шаге не требуются ингредиенты, система явно показывает «Ингредиенты не требуются» вместо пустого блока.
7. Если в рецепте отсутствует пошаговая инструкция, система показывает сообщение «Инструкция приготовления не добавлена» и не отображает пустые шаги.
