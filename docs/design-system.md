# Дизайн-система клиента

Документ описывает, из чего собраны экраны «Вход» и «Рецепт» (спринт 3, задача 4): токены, шрифты,
компоненты, адаптив и правила, по которым добавляется новый экран. Макеты лежат в
`frontend/design/` (четыре PNG, 1440 px), техническая часть клиента — в
[`docs/frontend.md`](frontend.md).

## 1. Откуда взяты значения

Figma-файл проекта закрыт (ссылка не открывается без авторизации), поэтому значения сняты
непосредственно с PNG:

- **палитра** — пипеткой ImageMagick по сплошным областям (`#234D39` кнопки, `#203F32` заголовков,
  `#FAF9F5` фона, `#EFF3E8` плашек, `#F7DECE` акцента, `#E4E7DE` границ);
- **сетка** — по координатам блоков на кадре 1440 px: контейнер 1280 px (поля по 80 px), у экрана
  входа внешние поля 32 px, карточка 662×860, колонка формы 420 px, карточка ингредиентов 438 px;
- **типографика** — по высоте строк и капитали: 44 px заголовок страницы, 30 px заголовок секции,
  22 px логотип, 15–16 px текст, 13 px подписи, 12 px капс;
- **шрифты** — по форме глифов: сериф с умеренным контрастом (Lora) и гротеск (Inter).

Если появится доступ к Figma, токены и размеры меняются точечно в `src/styles/tokens.css` — ни один
компонент не содержит собственных цветов и «магических» размеров.

## 3. Типографика

| Токен | Размер | Начертание | Где |
|---|---|---|---|
| `--text-3xl` | 44 px (30 px на мобильном) | Lora 400 | заголовки страниц: «С возвращением!», название рецепта, 404 |
| `--text-2xl` | 30 px (24 px) | Lora 400 | заголовки секций: «Ингредиенты», «Готовим шаг за шагом» |
| `--text-xl` | 22 px | Lora 500 | логотип «Recepie Book» |
| `--text-lg` | 18 px | Inter 600 | названия шагов |
| `--text-md` | 16 px | Inter 400 | поля ввода |
| `--text-base` | 15 px | Inter 400/500/600 | основной текст, кнопки, пункты навигации |
| `--text-sm` | 13 px | Inter 400/500 | подписи, мета, подвал, количества |
| `--text-xs` | 12 px | Inter 500 | капс-надзаголовки, подсказки статусов |

Капс-надзаголовки («РАДЫ ВАС ВИДЕТЬ») собраны как обычный текст + `text-transform: uppercase` и
`letter-spacing: 0.12em` (`--tracking-caps`): так текст остаётся нормальным для скринридера.

Шрифты — variable-сборки `@fontsource-variable/lora` и `@fontsource-variable/inter`, подключены в
`src/main.tsx` (`wght.css`). Это один woff2 на подмножество (latin, cyrillic, …) вместо десятков
файлов статических начертаний; браузер скачивает только нужные подмножества, CDN не используется.

## 4. Сетка, отступы, радиусы

| Токен | Значение | Смысл |
|---|---|---|
| `--container` | 1280 px | ширина контента на 1440 (поля по 80 px) |
| `--gutter` | 80 / 40 / 20 px | поля страницы на ≥1200 / 768–1199 / <768 |
| `--header-height` | 84 px (68 px) | высота шапки |
| `--space-1…12` | 4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80, 96 px | шкала отступов, только из неё |
| `--radius-sm…xl` | 8, 12, 16, 24 px | поля и кнопки — 12, карточки и фото — 24 |
| `--radius-pill` | 999 px | пилюли навигации, бейдж, номера шагов, аватар |
| `--shadow-card` | мягкая тень | карточка ингредиентов |
| `--shadow-raised` | тень сильнее | зарезервирована под поповеры |

Экран входа использует свои внешние поля 32 px (24/20 на узких): на макете фотокарточка стоит почти
у края, поэтому общий контейнер 1280 px к нему не применяется.

## 5. Брейкпоинты

| Ширина | Вход | Рецепт |
|---|---|---|
| ≥1200 | фотокарточка 662 px + форма 420 px по центру правой области | hero 690:545, контент 438 + остальное |
| 901–1199 | две колонки 1:1, фотокарточка 3:4 | колонки сжимаются пропорционально (1.25:1), карточка ингредиентов 380 px |
| 768–900 | одна колонка: фото сверху (16:10), форма под ним (max 480 px) | одна колонка: hero, затем контент |
| <768 | одна колонка, фото 4:4.2, форма на всю ширину | навигация скрыта, шаги и карточка в одну колонку, тайминг-метки под заголовком шага |

Мобильных макетов нет: эти ширины — производная вёрстка от кадра 1440 с сохранением порядка блоков,

## 6. Компоненты

| Компонент | Файл | Назначение |
|---|---|---|
| `Logo` | `components/brand/Logo.tsx` | тёмная плитка с глифом + серифный вордмарк, ссылка на `/` |
| `SiteHeader` (`variant: 'auth' \| 'app'`) | `components/layout/SiteHeader.tsx` | шапка до входа (ссылка «Создать аккаунт») и после (пилюли навигации, меню пользователя) |
| `SiteFooter` (`variant`) | `components/layout/SiteFooter.tsx` | две раскладки подвала из макетов |
| `AuthLayout`, `AppLayout` | `components/layout/` | общий каркас: шапка — контент — подвал, `min-height: 100vh` |
| `Button` | `components/ui/Button.tsx` | `primary` и `outline`, иконка слева (декоративная), `fullWidth`, `aria-pressed` для избранного |
| `TextField` | `components/ui/TextField.tsx` | подпись + поле, `id` обязателен, optional `trailing` |
| `PasswordField` | `components/ui/PasswordField.tsx` | `TextField` с кнопкой показа пароля (`aria-pressed`, меняющееся имя) |
| `Breadcrumbs` | `components/recipe/Breadcrumbs.tsx` | «← Лента рецептов / Название», текущий элемент с `aria-current` |
| `RecipeHero` | `components/recipe/RecipeHero.tsx` | фото с бейджем, заголовок, описание, мета, плашка наличия, избранное |
| `IngredientsCard` | `components/recipe/IngredientsCard.tsx` | список ингредиентов со статусами и плашкой аллергенов |
| `StepsList` | `components/recipe/StepsList.tsx` | нумерованные шаги, время и источник идеи |

Правила:

- каждый компонент — папка с `Component.tsx` и `Component.module.css`; глобальных классов нет,
  кроме `.sr-only` в `base.css`;
- в модулях только `var(--…)`: ни одного собственного hex или пикселя «на глаз»;
- состояния (`:hover`, `:focus-visible`, `[aria-pressed='true']`, `[data-available]`) описываются в
  модуле компонента, а не у страницы;
- интерактивный элемент без страницы (пункт навигации, «Создать аккаунт», меню пользователя)
  рендерится кнопкой с `aria-disabled="true"` и подсказкой — это честнее мёртвой ссылки. Когда
  появятся маршруты, кнопка заменяется на `Link` без правок стилей.

## 7. Данные и мок

`src/mocks/recipe.ts` содержит один рецепт из макета: `RecipeView`, `RecipeIngredient`,
`RecipeStep`. Формы намеренно близки к схемам `openapi.yaml` (`Recipe`, `RecipeStep`,
`RecipeNutrition`), поэтому переход на `GET /recipes/{id}` (спринт 4) заменит загрузку данных, но
не разметку. Идентификатор из адреса уже пробрасывается в контейнер страницы
(`data-recipe-id`), чтобы будущий запрос было куда подставить.

Статусы ингредиентов переданы текстом («Есть в холодильнике» / «Нужно добавить»), иконка лишь
повторяет смысл и скрыта от скринридера: цвет — не единственный носитель информации.

## 8. Ассеты

- `src/assets/login-hero.svg`, `src/assets/recipe-hero.svg` — аккуратные заглушки вместо фотографий
  из макетов (исходных файлов нет, а вытаскивать растровые фото из PNG с неизвестной лицензией
  нельзя). Замена: положить `jpg/webp` рядом и поменять один `import`.
- Логотип нарисован инлайн-SVG по мотивам макета; при появлении экспорта заменяется `<svg>` внутри
  `Logo.tsx`.
- Иконки — `lucide-react` (`Clock`, `ChefHat`, `Users`, `Heart`, `CircleCheck`, `CirclePlus`,
  `Leaf`, `Wheat`, `ArrowRight`, `ArrowLeft`, `ArrowUpRight`, `ChevronDown`, `Eye`, `EyeOff`).

## 9. Доступность

- у каждого поля — настоящий `<label for>`; `id`, `name`, `autoComplete`, `required` заполнены;
- кнопка пароля: `aria-pressed`, имя «Показать пароль» / «Скрыть пароль»;
- навигация — `<nav aria-label="Основная навигация">`, крошки — `<nav aria-label="Хлебные крошки">`
  с `aria-current="page"` у текущего элемента;
- декоративные иконки и фото-фон — `aria-hidden`, у фото рецепта осмысленный `alt`;
- `:focus-visible` даёт видимую рамку, `prefers-reduced-motion` отключает переходы;
- порядок заголовков: `h1` страницы → `h2` секций → `h3` шагов.

## 10. Как добавить компонент или страницу

1. Компонент: папка в `src/components/<область>/`, `.tsx` + `.module.css`, стили только из токенов.
2. Страница: файл в `src/pages/`, модуль рядом; путь — в `ROUTES` (`src/app/routes.ts`).
3. Лейаут: до входа — `AuthLayout`, после — `AppLayout` (в `src/App.tsx`).
4. Тест: роль + доступное имя (не класс и не цвет), в `src/__tests__/`.
5. Проверки: `npm run typecheck && npm run lint && npm run format:check && npm run test:coverage &&
   npm run build`.
6. Визуальная проверка: `npm run dev` и скриншоты headless Firefox
   (`firefox --headless --window-size=1440,1040 --screenshot ... http://localhost:3000/login`).

## 11. Ограничения этой задачи

- Figma недоступна, поэтому оттенки и размеры приближены по PNG; фотографии заменены заглушками.
- API не подключён: форма входа ничего не отправляет, страница рецепта показывает мок, избранное
  переключает только локальное состояние.
- Ссылки на ещё не созданные разделы (лента, холодильник, избранное, регистрация) отключены через
  `aria-disabled`; маршрутов под них пока нет.
- Пиксельного сравнения с макетом в CI нет (Playwright не входит в стек): сверка ручная, по
  скриншотам на 1440/1024/768/390.

типографической иерархии и тач-таргетов не меньше 44 px.
