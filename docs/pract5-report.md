Оценка техдолга примерная: сколько времени уйдёт на следующее изменение этого участка.
Подробности — в `docs/pract3-reviews/*.md`.

## Коротко по PR
01. parser
    Было: handle_starttag делал всё сразу.
    Стало: диспетчер и маленькие методы на каждый тег.
    Почему: длинный метод тяжело читать, а порядок проверок легко потерять.
    Проверка: pytest tests/test_importer_pages.py, полный pytest.

02. timer
    Было: active_timers закрывал просроченные и сразу читал список.
    Стало: close_expired_timers отдельно, active_timers только читает.
    Почему: у функции было два разных действия.
    Проверка: pytest tests/test_timers.py, полный pytest.

03. ingredients
    Было: одна функция с цепочкой isinstance.
    Стало: отдельные функции для строки, контейнера и пустого значения.
    Почему: у каждого формата своя логика, её проще тестировать отдельно.
    Проверка: pytest tests/test_importer_povarenok.py, полный pytest.

04. pageframe
    Было: AppLayout и AuthLayout почти одинаковые.
    Стало: общий PageFrame, два коротких файла.
    Почему: дублирование, при правке каркаса легко забыть второй файл.
    Проверка: npm run test:run, typecheck, lint, format:check, build.

05. engine
    Было: результат рекомендаций — список словарей.
    Стало: ScoredRecipe с четырьмя полями.
    Почему: опечатка в ключе не ловилась до запуска.
    Проверка: test_ml_engine.py, test_recommendation_model.py, полный pytest.

06. enrich
    Было: восемь параметров у enrich_recipes.
    Стало: db + EnrichOptions.
    Почему: вызовы стало проще читать, настройки собраны в одном месте.
    Проверка: test_importer_pages.py, полный pytest.

## Что не меняли
- адреса API и HTTP-коды;
- названия полей JSON;
- таблицы и колонки БД;
- поведение для тех же входных данных.

## Что осталось
- В enrich остался широкий Callable, полный протокол не делали.
- В engine recipe остался dict: отдельный тип для рецепта — другая задача.
- В timer транзакцию специально не добавляли, поведение оставили прежним.
