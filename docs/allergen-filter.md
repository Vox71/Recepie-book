# Фильтр аллергенов и непереносимостей (спринт 2, задача 6.1)

Документ фиксирует, как устроена фильтрация рецептов по аллергиям, на каких данных она измерена
и какие ограничения остаются. Дополняет [`docs/sprint-2-plan.md`](sprint-2-plan.md) (задача 6.1)
и [`docs/db_schema.md`](db_schema.md) (таблица `recipe_ingredients`).

## Задача и критерий приёмки

Цель — не отдавать пользователю рецепт, в котором есть продукт из его аллергий, и при этом не
выбрасывать безопасные блюда из-за похожих слов. Критерии задачи:

| Критерий | Значение | Где проверяется |
|---|---|---|
| `violation_rate` (доля пропущенных аллергенов) | **0.000** | `python -m app.ml.allergen_eval`, `tests/test_allergens.py` |
| precision / recall / F1 на размеченной выборке | **1.000 / 1.000 / 1.000** | там же; числа зафиксированы ниже |
| «Похожие, но не аллергены» не срабатывают | 23 случая | `test_lookalikes_do_not_trigger_unrelated_allergens` |

Пропущенный аллерген — риск для здоровья, поэтому критерий по `violation_rate` жёсткий: одна
ошибка уже проваливает прогон (`allergen_eval` возвращает код 1).

## Как устроен словарь

`backend/app/ml/allergens.py`. Группа — это `slug`, человекочитаемое название, список словоформ
(русских и английских) и два вида правил против ложных срабатываний:

```python
AllergenGroup(
    slug="gluten",
    title="Глютен (злаки)",
    terms=("мука", "хлеб", "макароны", "овсяные хлопья", "flour", "bread", ...),
    blockers=(("гречк",), ("рисов",), ("кукуруз",), ("соев", "мук"), ...),
    exceptions=("печень", "печени", "печенью"),
)
```

| Поле | Смысл | Пример |
|---|---|---|
| `terms` | продукты группы в любых словоформах; перед сравнением лемматизируются | `молоко` находит `молока`, `молоком` |
| `blockers` | фраза (набор префиксов токенов), которая делает ингредиент безопасным заменителем | `кокос` отменяет молоко для «кокосового молока»; `("соев", "мук")` отменяет глютен только для соевой муки, но не для соевого соуса |
| `exceptions` | точные токены-двойники, которые не должны срабатывать | `сырой` — не `сыр`, `печень` — не `печенье`, `eggplant` — не яйцо |

13 групп: `milk`, `gluten`, `eggs`, `soy`, `peanut`, `nuts`, `fish`, `seafood`, `sesame`,
`mustard`, `celery`, `sulphites`, `lupin` — то же деление, что в маркировке ЕС, плюс отдельный
арахис. Термин пользователя («молочные продукты», «глютен», «креветки») раскрывается в группу
(`ALLERGEN_ALIASES`); термин, которого нет в словаре («киви»), не исчезает, а сравнивается по
лемме со строками ингредиентов.

## Откуда берутся ингредиенты

Правило задачи — фильтровать по `recipe_ingredients`, а не по тексту `recipes.ingredients`:

| Источник | Когда используется | Почему |
|---|---|---|
| `recipe_ingredients` (строка на ингредиент, заполняет импортёр povarenok) | всегда, если строки есть | текст рецепта не отличает «молоко» от «кокосового молока», а нормализованные строки — отличают |
| `recipes.ingredients` (текст) | только если строк нет (рецепт создан через `POST /recipes`) | иначе такой рецепт прошёл бы фильтр непроверенным |

Загружает строки `app/models/recipes.py::list_ingredient_names` (один запрос на страницу
рецептов), фильтрует `app/services/allergen_service.py::filter_safe_recipes`. Один и тот же
фильтр используют обе ветки `GET /recommend_recipes`: базовая логика и ML-модуль
(`app/ml/engine.py` получает готовую карту «рецепт → ингредиенты»).

## Метрики на размеченной выборке

Выборка — `backend/tests/data/allergen_labeled_sample.json`: **211 рецептов, 259 меток**.
Каждый рецепт размечен вручную: перечислены группы, которые человек видит в списке ингредиентов
(пустой список — безопасное блюдо). В выборке есть все 13 групп, комбинированные блюда
(сырники, паста карбонара, сельдь под шубой), английские названия и «ловушки»: кокос, гречка,
рисовая и кукурузная мука, мускатный орех, «сырой картофель», печень, икра кабачковая,
томатная паста, безглютеновый хлеб, соевый и растительный белок.

Как считается: для каждого рецепта сравниваются множество размеченных групп и множество,
которое вернул фильтр. `tp`/`fp`/`fn` считаются по парам «рецепт, группа», `violation_rate = fn /
число меток`. Скрипт возвращает код 1, если `violation_rate > 0` или F1 ниже порога
(`--fail-under-f1`, по умолчанию 0.95).

## Как воспроизвести

```bash
cd backend
python -m app.ml.allergen_eval                  # таблица + вердикт
python -m app.ml.allergen_eval --json           # те же числа машинно-читаемо
python -m app.ml.allergen_eval --fail-under-f1 1.0 --max-violation-rate 0
python -m pytest tests/test_allergens.py       # 10 кейсов, из них 7 без базы
```

Тест `test_labelled_sample_has_no_missed_allergens` прогоняет ту же выборку внутри `pytest`,
поэтому регрессия словаря падает на CI, а не только при ручном запуске скрипта.

## Ограничения и что делать дальше

| Ограничение | Почему так | Что предлагается |
|---|---|---|
| Выборка размечена синтетически (211 рецептов, написанных для проверки), а не взята из датасета | датасет povarenok (~147 тыс. рецептов) не коммитится и в CI недоступен | разметить 200–300 случайных рецептов из скачанного датасета и прогнать `allergen_eval --sample <файл>`; метрики в таблице выше — in-sample |
| Метрики измерены на том же словаре, которым размечена выборка | иного источника разметки у учебного проекта нет | при разметке датасета размечать вслепую: сначала список ингредиентов, потом сверка со словарём |
| Учитываются только ингредиенты, а не рецептура производителя | в датасете есть только названия продуктов | состав полуфабрикатов («майонез», «колбаса», «печенье») считается по названию, а не по упаковке |
| Аллергены, не входящие в группы («киви», «кокос»), находятся только по буквальному совпадению лемм | словарь покрывает 13 групп маркировки, а не все продукты | добавлять группы по мере появления запросов от пользователей |
| Овёс отнесён к глютену, сульфиты находятся только по слову «сульфиты»/«диоксид серы» | овёс входит в список злаков ЕС, а вино/курага без маркировки не распознаются | решить с продукт-овнером, нужно ли смягчить правило для овса |
| Названия блюд, а не только продуктов, распознаются ограниченно («крабовые палочки» → морепродукты, но не рыба) | сурими делают из рыбы, а в названии этого нет | добавить состав полуфабрикатов, если появится источник данных |

## Решения, которые стоит знать

- **Словарь в коде, а не в таблице БД.** `docs/db_schema.md` оставлял такой вариант как
  допустимый: справочник меняется вместе с правилами фильтра, проходит code review и не требует
  миграции. Если словарь начнут править не разработчики, его стоит перенести в таблицу.
- **Фильтр не удаляет рецепты, а отбрасывает их из выдачи.** `GET /recipes` по контракту отдаёт
  все рецепты; фильтрация применяется к рекомендациям. Отдельный адрес «безопасных рецептов» —
  вопрос к продукт-овнеру и контракту (`openapi.yaml`).
- **Блокировки проверяются по токенам, а не по подстроке ингредиента.** Поэтому «масло
  растительное» не считается молоком, а «сырой картофель» — сыром: сравнение идёт по словам,
  а не по вхождению строки.
