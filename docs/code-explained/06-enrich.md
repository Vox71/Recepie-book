# Обогащение рецептов: `backend/app/importer/enrich.py`

## Что делает модуль

Импорт датасета создаёт рецепт с `source_url`, названием и ингредиентами. `enrich.py` берёт
рецепты, у которых есть ссылка, скачивает страницу, разбирает её через `pages.py` и записывает:

- шаги в `recipe_steps`;
- время, порции и текст инструкции в `recipes`;
- КБЖУ в `recipe_nutrition`.

Модуль идемпотентный: повторный запуск не трогает уже разобранные страницы.

## Поток данных

```text
CANDIDATES_SQL → список (id, source_url)
    ↓
load_page() → HTML из кеша или сети
    ↓
parse_recipe_page() → ParsedPage
    ↓
save_page() → UPDATE recipes + INSERT steps + UPSERT nutrition
```

## Константы и SQL

| Строки | Что | Почему |
|---|---|---|
| 49–51 | `PARSER_VERSION = "pages/1"` | Позволяет переразобрать строки после изменения парсера |
| 52–56 | `DEFAULT_*`, `MAX_CONSECUTIVE_FAILURES`, `DEFAULT_CACHE_DIR` | Значения CLI и защита от блокировки сайта |
| 58–65 | `CANDIDATES_SQL` | Выбирает только неразобранные/устаревшие рецепты; `force` снимает фильтр |
| 67–75 | `UPDATE_RECIPE_SQL` | `COALESCE` не затирает уже заполненные поля пустым значением |
| 77–81 | `DELETE_STEPS_SQL`, `INSERT_STEPS_SQL` | Шаги перезаписываются целиком, чтобы не смешивать старые и новые |
| 82–98 | `UPSERT_NUTRITION_SQL` | Одна строка КБЖУ на рецепт; `ON CONFLICT` обновляет её |

Почему `COALESCE`: если на странице не было времени, `NULL` не должен стереть время, которое
уже было в базе.

Почему `DELETE` + `INSERT` для шагов: шагов может стать меньше; обновлять по одному сложнее, чем
переписать набор.

## `EnrichmentStats`

Строки 101–129 — счётчики запуска. Они не влияют на данные, но нужны для лога и тестов:
`candidates`, `fetched`, `from_cache`, `updated`, `without_steps`, `failed`, `stopped`.

`as_dict()` нужен, чтобы CLI вывел один JSON. Это проще, чем собирать строку вручную.

## `load_page`

| Строки | Что | Почему |
|---|---|---|
| 152 | `path = cache_path(...)` | Имя файла — `<recipe_id>.html` |
| 153–154 | Если файл есть и нет `refresh` | Повторный запуск не ходит в сеть |
| 156–158 | `time.sleep(delay)` | Вежливость: не бомбить сайт запросами |
| 159 | `opener(url, timeout=timeout)` | Сеть изолирована в одной функции; `opener` подменяется в тестах |
| 160–161 | Создание папки и запись HTML | Следующий запуск сможет работать офлайн |
| 162 | `return html, False` | `False` означает «скачано, не из кеша» |

Почему кеш: повторный разбор после исправления парсера не должен снова скачивать сотни страниц.

## `enrich_recipes` построчно

| Строки | Что | Почему |
|---|---|---|
| 183 | `db.fetch_all(CANDIDATES_SQL, ...)` | Один запрос за списком кандидатов |
| 184 | `stats = EnrichmentStats(candidates=len(rows))` | Сразу фиксируется размер пачки |
| 185 | `blocked = 0` | Счётчик подряд идущих блокировок |
| 186–188 | Цикл по строкам | `recipe_id` и `url` приводятся к нужным типам |
| 189–199 | `load_page` + `parse_recipe_page` | Сеть и разбор внутри `try` |
| 200–208 | `except PageError` | Одна плохая страница не должна останавливать весь импорт |
| 203 | `blocked = blocked + 1 if _is_blocked(exc) else 0` | Считаются только подряд идущие блокировки |
| 204–207 | `if blocked >= MAX_CONSECUTIVE_FAILURES` | Если сайт начал блокировать, лучше остановиться |
| 210 | `blocked = 0` | Успешная страница сбрасывает серию |
| 211–214 | `from_cache` / `fetched` | Разделение статистики |
| 215 | `_count_page(stats, page)` | Счётчики «без шагов/времени/порций» |
| 216–218 | `dry_run` | Разбор без записи в БД |
| 219 | `save_page(db, recipe_id, page)` | Запись одной транзакцией |
| 220 | `stats.updated += 1` | Успешное обновление |
| 221–228 | Лог по рецепту | Полезно при разборе большого импорта |
| 229 | `return stats` | CLI получает итог |

Почему `try` охватывает и загрузку, и разбор: и сеть, и битый HTML дают `PageError`.

Почему `continue`, а не `break` на обычной ошибке: одна страница не должна отменять остальные.
`break` только при серии блокировок.

## `save_page`

Строки 232–...:

- `with db.cursor()` — одна транзакция на рецепт;
- `UPDATE recipes` заполняет время/порции/инструкцию;
- `DELETE recipe_steps` и `INSERT` заново;
- `UPSERT recipe_nutrition`.

Почему одна транзакция на рецепт: если запись упадёт в середине, не должно остаться полусостояние
«шаги новые, КБЖУ старые». Остальные уже обработанные рецепты при этом сохраняются.

## `cli.py`

Строки 151–169: CLI проверяет `--enrich`, создаёт `Database` и вызывает `enrich_recipes` с
параметрами из аргументов. `args.limit or DEFAULT_LIMIT` означает: если `--limit` не задан,
берётся значение по умолчанию.

## Почему восемь параметров — проблема

Сейчас вызов выглядит так:

```python
enrich_recipes(
    database,
    limit=args.limit or DEFAULT_LIMIT,
    delay=args.delay,
    force=args.force,
    refresh=args.refresh,
    cache_dir=args.pages_dir,
    timeout=args.timeout,
    dry_run=args.dry_run,
)
```

Плюс `opener` в тестах. Читатель должен помнить восемь имён. Если добавить новую настройку,
придётся править все вызовы. `EnrichOptions` собирает их в один объект:

```python
@dataclass(frozen=True)
class EnrichOptions:
    limit: int = DEFAULT_LIMIT
    delay: float = DEFAULT_DELAY_SECONDS
    ...
```

Почему `frozen=True`: настройки одного запуска не должны меняться в процессе.

## Почему не альтернативы

- **Отдельный воркер** — импорт запускается вручную, это не пользовательский запрос.
- **Скачивать без кеша** — долго и невежливо к сайту.
- **Обновлять шаги по одному** — сложнее, чем переписать набор.
- **Хранить настройки в глобальных переменных** — тесты не смогут запускать разные режимы
  параллельно.
- **Хранить время обнаружения вместо `ends_at`** — в enrich нет `closed_at`, но принцип тот же:
  хранить факт, а не время его обнаружения.

## Что спросит преподаватель

1. Почему `COALESCE`? — не затирать уже найденные поля пустым значением.
2. Почему `parser_version`? — после изменения парсера нужно переразобрать старые строки.
3. Почему `dry_run`? — проверить разбор без записи в БД.
4. Почему `opener` — аргумент? — тесты подменяют сеть, не ходя в интернет.
5. Почему `MAX_CONSECUTIVE_FAILURES`? — не долбить сайт, который отвечает блокировкой.
6. Почему настройки собираются в `EnrichOptions`? — вызов становится короче, порядок аргументов
   нельзя перепутать, новая настройка добавляется в одном месте.
