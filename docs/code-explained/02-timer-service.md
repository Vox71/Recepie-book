# Таймеры: `timer_service.py`, `models/timers.py`, `api/timers.py`

## Что делает эта часть

Пользователь открывает рецепт и нажимает «Старт». Сервер создаёт таймер с абсолютным дедлайном
`ends_at` и возвращает клиенту пару `ends_at` / `server_time`. Клиент считает остаток как
`ends_at - server_time`, а не по часам телефона.

Смысл: перезагрузка страницы, второй браузер и смена часового пояса не должны ломать таймер.

## Поток данных

```text
POST /timers
    → api/timers.py: start_timer()
    → timer_service.start_timer()
    → models/timers.create()
    → PostgreSQL: ends_at = now() + duration
    ← ответ: server_time + timer

GET /timers/active
    → close_expired()  (изменение)
    → list_active()    (чтение)
    ← server_time + список
```

## `models/timers.py` построчно

| Строки | Что | Почему |
|---|---|---|
| 17 | `TIMER_COLUMNS` | Список колонок в одном месте; не дублируется в SELECT |
| 21–23 | `TIMER_READ_COLUMNS` | Добавляет `remaining_seconds` и `server_time`, посчитанные одной БД |
| 26–34 | `count_active` | Проверка лимита активных таймеров; `status='running' AND ends_at > now()` |
| 37–44 | `create` | Вставляет строку и сразу возвращает её; `ends_at` считается в SQL |
| 47–59 | `close_expired` | Меняет статус просроченных на `finished`; `closed_at = ends_at` |
| 62–71 | `list_active` | Читает только идущие таймеры, сначала те, что закончатся раньше |
| 74–76 | `server_now` | Возвращает время БД, когда список пуст |
| 79–91 | `cancel` | Меняет статус на `cancelled`; `False`, если чужой/уже закрытый |

Почему `ends_at` вычисляется в SQL: `now()` и `ends_at` должны быть из одного источника времени.
Если считать `now()` в Python, а `ends_at` в БД, между ними появится расхождение.

Почему `closed_at = ends_at`, а не `now()`: таймер должен был закончиться в `ends_at`; время,
когда мы это заметили, не должно искажать историю.

Почему `cancel` возвращает `bool`: сервис не должен знать, сколько строк обновилось; ему важно
только «получилось или нет». Чужой таймер и несуществующий дают одинаковый `404`, чтобы не
раскрывать существование чужой строки.

## `active_timers`

Сейчас функция делает два действия:

| Строки | Что | Почему |
|---|---|---|
| 75 | `close_expired(db, user_id)` | Перед чтением закрывает всё, что уже истекло |
| 76 | `list_active(...)` | Читает оставшиеся активные таймеры |
| 79 | `rows[0]["server_time"]` или `server_now(db)` | Даже при пустом списке клиенту нужно «сейчас» |
| 80–83 | Сериализация | `iso_datetime` и `serialize_timer` приводят строки БД к JSON |

Почему закрытие без фонового воркера: один UPDATE идемпотентен, ничего не стоит, пока таймеров
нет, и не требует отдельного процесса. Воркер можно добавить позже, но для учебного проекта это
лишняя инфраструктура.

Почему `server_time` берётся из строки, если есть таймеры: значение уже посчитано тем же SQL, что
и `remaining_seconds`; отдельный запрос был бы лишним.

## Почему не альтернативы

- **Считать остаток на клиенте** — после перезагрузки остаток потеряется, а часы устройства могут
  быть неверными.
- **Хранить счётчик секунд** — его нужно постоянно обновлять; дедлайн в БД проще и надёжнее.
- **Фоновый воркер** — нужен для уведомлений, но не для того, чтобы список не показывал
  просроченные таймеры.
- **`timestamp` без зоны** — сломается при смене часового пояса и переходе на летнее время;
  используется `timestamptz`.
- **Возвращать только `remaining_seconds`** — клиент не сможет восстановить таймер после
  перезагрузки без опорного `server_time`.

## Что спросит преподаватель

1. Почему `ends_at` считается в PostgreSQL? — чтобы не смешивать часы Python и БД.
2. Почему `server_time` есть даже при пустом списке? — клиенту нужна точка отсчёта.
3. Почему `close_expired` вызывается в `active_timers`, а не в `create`? — список должен быть
   честным на момент чтения; создание таймера не должно закрывать чужие.
4. Почему `cancel` не различает «чужой» и «несуществующий»? — чтобы не раскрывать наличие
   чужих записей.
5. Почему `active_timers` стоит разделить? — потому что сейчас она и меняет данные, и читает;
   после разделения чтение можно вызывать безопасно.
