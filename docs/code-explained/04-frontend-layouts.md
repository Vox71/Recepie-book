# Каркас страниц: `frontend/src/components/layout`

## Зачем нужны два layout-файла

В приложении две визуальные оболочки:

- `AuthLayout` — экран входа: шапка без навигации, подвал с копирайтом;
- `AppLayout` — остальные страницы: шапка с меню пользователя, трёхколоночный подвал.

Обе оболочки используют один и тот же `Layout.module.css`, поэтому классы `page` и `main`
одинаковые. Сейчас разметка почти полностью дублируется; задача — вынести её в `PageFrame`.

## Как работает React Router

`App.tsx` описывает дерево маршрутов. Layout — это родительский маршрут с `<Outlet />`:

```text
<Route element={<AppLayout />}>
    <Route path="/recipes/:recipeId" element={<RecipePage />} />
    <Route path="*" element={<NotFoundPage />} />
</Route>
```

`Outlet` — место, куда React Router подставляет дочернюю страницу. Поэтому `AppLayout` не знает,
что именно внутри: рецепт, холодильник или 404.

## `AppLayout.tsx` построчно

Строки 1–5:

| Строка | Что | Почему |
|---|---|---|
| 1 | `import { Outlet }` | Нужен для дочерней страницы |
| 3–4 | `SiteFooter`, `SiteHeader` | Общие части оболочки |
| 5 | `styles` из CSS-модуля | Классы не глобальные, а локальные для компонента |

Строки 7–11 — docstring: объясняет, что здесь живут страницы после входа.

Строки 12–22:

| Строка | Что | Почему |
|---|---|---|
| 14 | `<div className={styles.page}>` | Колонка на всю высоту страницы |
| 15 | `<SiteHeader variant="app" />` | Вариант шапки с навигацией и меню |
| 16–18 | `<main className={styles.main}><Outlet /></main>` | Растягиваемая часть с текущей страницей |
| 19 | `<SiteFooter variant="app" />` | Трёхколоночный подвал |
| 21 | `</div>` | Закрывает общий каркас |

Почему `main`, а не `div`: это семантический тег, который помогает доступности и SEO. Почему
`Outlet` внутри `main`: страница должна быть в основной области, а не в шапке или подвале.

## `AuthLayout.tsx` построчно

Файл почти такой же. Отличия:

- строка 15: `<SiteHeader variant="auth" />`;
- строка 19: `<SiteFooter variant="auth" />`;
- docstring говорит про экран входа.

`variant` — строка `'auth' | 'app'`. `SiteHeader` и `SiteFooter` уже умеют переключать разметку
по этому значению, поэтому layout не дублирует их внутреннюю логику.

## CSS-модуль

`Layout.module.css` задаёт:

- `.page` — flex-колонка на минимум высоты экрана;
- `.main` — `flex: 1`, то есть забирает свободное место;
- благодаря этому подвал прижат к низу, даже если контента мало.

Если убрать `flex: 1` у `main`, подвал «прилипнет» к контенту и будет висеть в середине экрана.
Это не ошибка React, а следствие CSS.

## Почему сейчас дублирование

Два layout появились из двух макетов: у входа и у приложения разные шапки и подвалы. Разметка
контейнера и `main` оказалась одинаковой, но её скопировали, чтобы не трогать компоненты шапки
и подвала.

После рефакторинга:

```tsx
<PageFrame variant="auth" />
```

и

```tsx
<PageFrame variant="app" />
```

`PageFrame` содержит общий `<div>`, `<main>` и `<Outlet>`, а вариант передаёт в шапку и подвал.

## Почему не альтернативы

- **Оставить два файла** — при правке каркаса нужно помнить о двух местах; легко исправить
  только один.
- **Сделать `PageFrame` без `variant`** — тогда шапка/подвал не знали бы, какой вариант рисовать.
- **Использовать `children` вместо `Outlet`** — пришлось бы оборачивать каждую страницу вручную;
  `Outlet` уже даёт это через маршруты.
- **Вынести шапку и подвал в `PageFrame`** — они уже отдельные компоненты; их не надо
  переписывать.
- **Сделать отдельные `AuthPageFrame` и `AppPageFrame`** — снова два почти одинаковых файла.

## Что спросит преподаватель

1. Что такое `Outlet`? — место, куда маршрут подставляет дочернюю страницу.
2. Почему `PageFrame` не знает о страницах? — это каркас, а не маршрутизатор; страницы приходят
   через `Outlet`.
3. Почему `variant` строкой, а не boolean? — вариантов два, и строковый union `'auth' | 'app'`
   читается лучше, чем `isAuth`.
4. Почему CSS-модуль, а не глобальный CSS? — классы локальны, нет конфликтов имён.
5. Почему после рефакторинга тесты не меняются? — DOM и поведение остаются прежними, меняется
   только структура компонентов.
